## What this is

"Work-It" — a Next.js PWA for a 48-week year (weeks 1–6 are the 4-day upper/lower saddle; week 7+ one lower, Extra Upper, bonus core or class) with belt diplomas, used by a household of users authenticated via **email + 4-digit PIN** at `/login` (no name picker). New-athlete write-up: **`docs/WHAT_IS_WORKIT.md`** (keep it in sync when program rules change). Deployed on **Netlify** at `workitapp.fit` (legacy `workit.kervinapps.com`). New people join at `/join?h=gowanus`. Houses: **The OG** and **Gowanus**. Data lives in PlanetScale (MySQL, serverless HTTP driver). Coach voices: **Master Tom Iron** (`master`), **James Grey** (`james`, Grey for short), **Luna Meadows** (`luna`; old id `sergeant` still reads), and **Eli Sparks** (`eli`; high-energy, encouraging, believes-in-you register — distinct from Tom's control and Luna's calm). Shouts fill `{name}` with **alias, else first name** (`athleteCallName` / `fillCoachName`). Keep **man** as a type (good men, the man who walked in), not a greeting — awkward titles are `{name}. That is growth.` Prize and punishment are **growth, lean, definition, power, stamina, mobility** (pay or withhold). Not come-home / aftercare / sexual. Tom is implication and control; quit is a noun, not `sissy`. Grey is British want, gym-plain, not office talk. Luna follows the picker too: calm, soft, hard work. Nicole McPherson register. UI tone: **gold** = take this action (Start, Now, Invite, Complete, Resume). **Earth green** (`#6d8b6e`) = done / good. **Earth red** (`#a35d52`) = still a problem. **Copper** (`#c08457`) = the house (avg, pack, You / house). **Cream** = you.

## Architecture

**Auth flow**: Session-based, not NextAuth. `lib/session.ts` issues/verifies an HS256 JWT (`jose`) in the `workit_session` cookie, signed with `AUTH_SECRET` (≥32 chars). `lib/auth.ts` wraps PIN hashing (scrypt), in-memory lockout (resets on redeploy), `requireCurrentUser`/`requireAdmin`, prefs, and house context (`last_household_id`). Login is **email + 4-digit PIN** at `/login` (`POST /api/auth/login`). Name picker is gone. `/` and `/who` → `/home` if session, else `/login`. Unauthenticated pages → `/login`; APIs → 401 JSON. Public: `/login`, `/join`, `/waiver`, `/faq`, `/api/auth/*`, `/api/join`, `GET /api/users`, cron, analytics event. New Gowanus people: `/join?h=gowanus` then verify mail (`/login?verify=`); `/login` blocked until `email_verified_at`. Invitees: `/join?h=…&claim=` (old `/who?claim=` redirects). New athletes default `coach_tone` to **`eli`** — public join sets it directly (`app/api/join/route.ts`); invite-created rows also set it explicitly at creation (`app/api/invite/route.ts`), so the claim flow's `COALESCE(coach_tone, 'eli')` has something real to preserve instead of silently losing to the `users` table's `master` schema default. Admin-added athletes (`POST /api/users`) still fall through to that `master` schema default — untouched. Forgot PIN mails `/login?reset=`. Invitees created with `pin_hash` NULL. User id `1` is admin of every house he is in. Houses: **The OG** (`og`, invite only) and **Gowanus** (`gowanus`, public join). `migrate-households.sql` (hand SQL; re-run = duplicate).

**Hyrox Training** (opt-in 16-week track; this build ships the mechanism + Phase 1/weeks 1-4 + Milestone 1 only — Phases 2-4 are a later content pass): unlocks once an athlete has **6 locked weeks** in the normal 48-week program (`lib/hyroxEligibility.ts`, reuses `lockedWeekCount`). Entry points: a "Hyrox Training" `AppMenu` item once eligible (`hyroxAvailable` prop) and a `HyroxRewardBanner` (medal SVG, Hyrox-red glow) on Home — one-time celebratory copy the first time, a plainer repeat row after, both localStorage-gated (not DB-tracked, a deliberate lighter-weight choice vs. `week_takeover_seen`). The menu item can't just `router.push('/home')` — that's a no-op when already on Home — so on Home it calls `onHyroxClick` to open the takeover directly, and from any other page it navigates to `/home?hyrox=1`, which Home reads on mount and cleans from the URL. Selecting it shows `HyroxIntroTakeover` (fixed copy, not coach-line-driven: what it is, starts Monday, what a workout looks like, the Milestone 1 challenge) before `POST /api/hyrox {action:'start'}` snapshots the athlete's current normal-program position into `hyrox_state.normal_week_at_start`/`normal_day_at_start` — idempotent against a double-call while already active (would otherwise reset `started_at` and silently hide already-logged sessions from that run). While `hyrox_state.active`, Home fully replaces its render with `HyroxHome` and `/workout` operates entirely in Hyrox mode (fetches `/api/hyrox` on mount into a `hyroxLoaded` flag that the session-resume effect waits on, so resuming an open Hyrox session can't race and briefly render blank against the wrong program array): Select Workout and the live session both read from `lib/hyroxProgram.ts` instead of `workoutProgram`, and the live session gets a real "Hyrox Red" wash (`.hyrox-session` in `globals.css`, black ground + red `.glass-header`/`.glass-card` accents — see `public/hyrox-session-preview.html` for the option set it was chosen from) instead of the belt wash. `workout_sessions.program_track` is derived **server-side** in `POST /api/sessions` from `weekNumber > HYROX_WEEK_OFFSET`, never trusted from the client. Hyrox week numbers are namespaced at **101+** (`HYROX_WEEK_OFFSET`/`hyroxDisplayWeek()` in `lib/hyroxProgram.ts`) so they can never collide with the normal program's 1-48 in shared `week_number`-keyed queries.

Each Hyrox week has exactly 5 training days (Mon run / Tue lower+sled / Wed active recovery / Thu upper+compromised-run / Sat full-body; Fri+Sun are the only true rest). Every movement is its own loggable `Exercise` — a Sled Push Alt round, a Compromised Run round, and a Finisher round are each split into 2-3 real exercises (`sledMovements`/`compromisedMovements`/`finisherMovements` in `lib/hyroxProgram.ts`) rather than one fake exercise with a circuit description crammed into its reps string. Consecutive movements from the same circuit share a `circuitGroup` label — `ExerciseTracker` renders a red "Circuit · Step N of M" badge on each card (the first also spells out the round-robin order in plain language) and `Exercise.noRestAfter` suppresses the shared rest timer between them, firing it only after the round's last movement. Where a movement matches a normal-program pattern, it keeps that program's exact exercise name (Barbell Back Squats or Goblet Squats, Romanian Deadlifts (RDLs), Farmer's Carries, Plank Hold, etc.) so weight history and video lookup carry over instead of starting from zero. `lib/bonusDay.ts`'s `weekLocked()` takes an optional per-week `requiredCount` (default 4) so `findNextProgramDay` can pass `requiredDays(week).length` — Hyrox weeks need all 5, not 4, to lock; `lib/hyroxState.ts`'s `hyroxWeeksElapsed()` uses the same per-week count rather than `lib/belts.ts`'s hardcoded-4 `lockedWeekCount`. Continuous-time content the sets×reps model can't parse (a run, an AMRAP, easy bike/mobility) is logged by time instead: `getExerciseKind`/`parseTimedTarget` (`lib/exerciseKind.ts`) recognize "min"/"minutes" in the reps text the same way they already recognized "seconds", routing it through the existing Start-timer/Stop-completes clock (same one Plank Hold uses) instead of a Weight/Reps form; `Exercise.estimatedMinutes` separately overrides the Select-Workout duration estimate for that same content (`lib/estimateDuration.ts`, additive, untouched for the normal program's 200+ entries).

A `WorkoutDay.milestone` field flags benchmark days (only `milestone: 1` so far, Week 4 Day 4; its self-report checklist quantities in `HYROX_MILESTONE_CRITERIA` are pulled from that day's actual exercises, not re-typed). Finishing that day shows `HyroxMilestoneTakeover`, a self-reported pass/fail checklist, and `POST /api/hyrox {action:'milestone'}` — server-validated against `hyrox_state.active` and against the athlete actually having a completed session on that exact day this run — records the result and, on pass, awards a tier in the separate `hyrox_diplomas` track (independent of the belt chest — `HyroxDiplomas`). A fail offers **Retry**, which starts a brand-new session for that same day (`startWorkout(..., { forceNew: true })`) since the failed session is already saved `is_completed=1` and `findNextProgramDay` would otherwise just skip past it, or **Drop**. Drop and any other exit `POST /api/hyrox {action:'drop'}`, computing `resumeWeek = normal_week_at_start + hyroxWeeksElapsed` and overwriting `normal_week_at_start` with it (the floor the normal program resumes at, via `findNextProgramDay`/`defaultSelectWeek`/`getTodayTarget`'s optional `minWeek` param in `lib/nextWorkout.ts`, passed from Home as `resumeFloor`). Leaving and starting over always begins at Week 1: `hyroxSessionsThisRun()` in `app/api/hyrox/route.ts` scopes every "what's next"/"weeks elapsed" computation to sessions completed at-or-after the *current* run's `hyrox_state.started_at`, so a prior (ended) run's completed sessions can't make the new run look like it's already partway done. "Leave Hyrox Training" lives in `AppMenu`'s footer (not a standalone page link) behind a confirmation `Modal` that states this restart-from-Week-1 consequence plainly.

`HyroxHome` reuses three normal-Home widgets against Hyrox-only data: `WeekLock`/`WeekPerformance` (already take a plain `WeekPlan` + `sessions` array as props, so they needed no changes — Hyrox's own namespaced week numbers keep their internal `/api/athlete-performance` calls naturally scoped) and `HomeTodayKpis`/`HomeKpiLead` (needed a new `track?: 'hyrox'` prop threaded into `useHomeBoard()`, which now caches per-track in a `Map` instead of one shared module-level variable, plus `lib/athletePerformance.ts`'s `athletePerformance()`/`athletePerformanceWithSnapshot()` gained an optional `programTrack` param — `AND ws.program_track = ?` — and skip the house-snapshot lookup entirely when track-scoped).
